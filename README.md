# SAT-solver-AC
Алгоритм реализован на языке C++.
Идея написать данный алгоритм пришла ко мне в 2025 году при подготовке к ЕГЭ по информатике в 11 классе.
Один из сложных прототипов - когда нужно выполнить процессы так, чтобы на каком-то отрезке времени их выполнялось как можно больше и этот отрезок был максимальным. В КИМ ЕГЭ это задача 22.
На практике обратную задачу часто приходится решать при проектировании планировщика процессов в операционной системе, чтобы не перегрузить диск или процессор.
Также это имеет применение в компиляторах при анализе области видимости переменных: можно составить диаграмму, на которой по оси ординат расположатся сами переменные, а на оси абсцисс - их временной диапазон видимости.
На ЕГЭ предлагается решить такую задачу аналитически, что часто довольно трудно и требует насмотренности.
Структура репозитория:
1. README.md - описание репозитория
2. AC.cpp - исходный код на C++. Чтобы адаптировать его под свою задачу, нужно изменить строки 5 и 6, ввод данных из консоли/файла не предусмотрен, но его можно внедрить, изменив только строки 5 и 6 - логика программы не изменится. Результат программы - число, максимальный отрезок времени в миллисекундах, в который выполняется максимальное количество процессов.
3. Сложность алгоритма.xlsx - в левом верхнем углу есть 2 ячейки, в которые можно ввести свои данные. Жёлтая ячейка - общее количество рассматриваемых процессов. В рамках экзамена там часто от 12 до 17 процессов. Зелёная ячейка - скорость рассмотрения, итераций/секунду. При такой реализации - за раз программа рассматривает около 130'000 вариантов. В шапке таблице указано количество процессов. За одну итерацию сдвигается не больше этого числа процессов. В 2-м столбце показано максимальное время сдвига каждого процесса. В первой таблице (белой, без условного форматирования) указано количество итераций, которые должна выполнить программа, чтобы гарантированно дать оптимальный результат (при выставленном ограничении времени сдвига (столбец таблицы) и количестве процессов для сдвига (строка таблицы)). Во второй таблице (с условным форматированием) указано время выполнения программы при заданной скорости (зелёная ячейка, по умолчанию - 130'000 итераций в секунду).
4. Решение 22 задач.pdf - инструкция для выпускников с описанием границ применимости алгоритма (для каких задач подходит) и его сложности (откуда получается таблица в п. 3)
- По опыту: наиболее оптимальный выбор для экзамена - сдвиг до 4 процессов включительно и до 20 миллисекунд включительно.
